# Handoff: iMessage Exporter GUI

Date: 2026-06-18

This package is a source-only handoff for continuing development on another Windows computer. It intentionally excludes caches, build output, installers, screenshots, local signing keys, and Git metadata.

## Project Snapshot

- Repository: `https://github.com/A1mAssist/imessage-exporter-gui`
- Local branch before packing: `codex/ci-exporter-compat-smoke`
- Last committed revision before packing: `375ee22` (`Polish conversation-based export naming`)
- App version in `package.json` and `src-tauri/Cargo.toml`: `0.2.0`

- Export engine: `imessage-exporter` Rust source is vendored under `src-tauri/vendor/imessage-exporter`; the app now uses the built-in engine path. A separate `imessage-exporter.exe` is not required for normal app development or use.

The working tree had active UI and smoke-test changes when this handoff was made. The source package contains the current working tree source, not only the last committed revision. Generated preview screenshots are excluded from the zip.

## Windows Development Environment

Recommended install path is a normal user-writable directory such as:

```powershell
D:\Workspaces\imessage-exporter-gui
```

Required tools:

- Windows 10/11.
- PowerShell 5.1 or newer.
- Git, if the new machine should push/pull from GitHub.
- Node.js with npm. This handoff was verified with Node `v24.15.0` and npm `11.12.1`; Node LTS/current in the same generation should work.
- Rust via rustup, using the stable MSVC toolchain. This handoff machine used Rust/Cargo `1.96.0`.
- Visual Studio Build Tools 2022 with the C++ workload and recommended Windows SDK components. `link.exe` and `kernel32.lib` must be visible to native builds.
- Microsoft Edge WebView2 Runtime for Tauri.
- Chrome or Edge installed for mock UI smoke tests. The smoke script uses the system browser executable through `playwright-core`.

Optional tools:

- `ffmpeg`, for attachment conversion workflows.
- ImageMagick (`magick`), for image conversion workflows.
- GitHub CLI (`gh`), if release or PR automation is needed.

The project has a helper setup script:

```powershell
.\scripts\setup-windows.ps1
.\scripts\setup-windows.ps1 -Install
.\scripts\setup-windows.ps1 -Install -InstallOptionalTools
```

After installing Node, Rust, or Visual Studio Build Tools, restart PowerShell so `PATH` and MSVC environment discovery are fresh.

## Restore Steps On A New Computer

1. Unzip the handoff package.

2. Open PowerShell in the project root.

3. Install JavaScript dependencies:

```powershell
npm install
```

4. Check the native toolchain:

```powershell
.\scripts\doctor.ps1
```

5. Run the standard frontend/static validation:

```powershell
npm run check:static
npm test
npm run build
```

6. Run Rust validation:

```powershell
Push-Location src-tauri
cargo test
cargo check
Pop-Location
```

7. Run the mock UI smoke test:

```powershell
$env:MOCK_UI_PORT='1422'
npm run smoke:mock-ui
```

Expected successful smoke output includes:

```txt
Mock UI smoke passed.
```

8. Start mock frontend development:

```powershell
npm run dev:mock
```

Open:

```txt
http://127.0.0.1:1421/?mock=1&lang=zh-CN&updateAvailable=1
```

9. Start the full Tauri app:

```powershell
npm run tauri dev
```

10. Build installers when the native toolchain is ready:

```powershell
npm run tauri build -- --no-sign
```

or:

```powershell
npm run package:windows
```

## Notes For The Next Agent

- Do not reintroduce a requirement for users to pick or validate an external `imessage-exporter.exe`; the built-in Rust engine is the product direction.
- Keep export preflight visible before export starts. Invalid real export runs should be blocked only when the user tries to start the run.
- The user dislikes fake explanatory filler, redundant status text, and ellipsis caused by cramped cards. Prefer direct labels, visible values, and layouts that do not hide important text.
- The user wants mock mode to be useful for visual QA, especially update/about/export-result surfaces.
- Before release work, run installed-app smoke against the actual packaged app, not only the mock frontend.
